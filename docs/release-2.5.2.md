# 工时账本 2.5.2 发布说明

- 版本：2.5.2
- 日期：2026-11-02
- 基线：2.5.1（234 个测试）
- 主题：**把并发与结算的「不知道」变成「看得见」**

## 1. 为什么是 2.5.2

2.5.1 修掉了会算错钱、会丢数据的问题。审计里还留了两处「不是 bug、但用户可能不知道」的风险，这一版把它们显式化：

- 两个窗口同时记账时，同一份 localStorage 只能 last-write-wins，用户无从得知自己正在制造冲突；
- 某个月已经标记「已到账」后，再改那个月的记录会悄悄改变「应发」与差额。

两处都不改数据格式与计薪口径，只加提示。

## 2. 范围

| 方向 | 内容 | 验收 |
| --- | --- | --- |
| 多窗口提醒 | `BroadcastChannel` 心跳（5s / 超时 15s）检测其它窗口，顶部提示；收到 `bye` 或超时后自动消失；可「知道了」忽略 | 开两个窗口出现提示，关掉一个提示消失 |
| 结算提醒 | 编辑已到账月份的记录时，面板提示改动会影响应发与差额；跟随记录日期变化 | 已到账月份出现提示，待到账/其它月份不出现 |

### 明确不做

- **逐条合并**：需要墓碑标记表达「删除」，要升级存储 schema 与备份格式，成本远高于收益，继续留待后续版本。
- **冻结结算快照**：现有「应发按当前记录重算 + 显示差额」是对账语义，冻结会把对账能力削掉；按用户选择保留重算，改为编辑时提示。

## 4. 已知限制

- 多窗口提醒依赖 `BroadcastChannel`；极老 WebView 不支持时静默降级为「不提示」，不影响功能。
- 提示只在「检测到第二个窗口」时出现，不阻止并发写；用户坚持两个窗口同时编辑时仍是 last-write-wins。
