# 工时账本 2.1：同类产品对比与动效打磨

> 调研与实现时间：2026-10-26  
> 对比对象：安心记加班、排班助手、记工时、Supershift、HoursTracker、Clockify、Toggl Track  
> 本文分两部分：前半部分回答「别人做得好的功能是什么」，后半部分记录「这一版把哪些动效真正落到了代码里」。

---

## 1. 一句话结论

工时账本在「计薪深度」和「本机优先」上已经不输同类：分段加班、收入预测、排班对账、工资结算、年度复盘这些链路比大多数记工时 App 更完整。  
真正拉开体验差距的，是**第一次打开时的顺手程度**和**每次操作后的反馈**：同类头部产品把力气花在「滑动月历」「拖拽面板」「数字滚动」「小组件」「班次闹钟」这些高频小动作上，而我们的 2.0 仍然偏「表单工具」：页面切换只有单向淡入，浮层只能点关闭，金额和图表是硬切，系统级触感也没有。

因此 2.1 不急着堆新功能，先把这些「每天会重复几十次」的动效和手感补齐；同时把竞品功能拆成一张有优先级的路线图，避免为了对比而对比。

### 2.2 我们真正建立起来的差异点

1. **计薪模型更深**：分段加班规则会写进记录快照，改设置不影响历史；排班、打卡结算、工资条、CSV 共用一套算法（`src/pay.ts`）。
2. **闭环更完整**：排班 → 系统提醒 → 打卡 → 漏记处理 → 对账 → 工资结算 → 工资条 → 备份，这个闭环在同类里不常见。
3. **数据更可控**：JSON 完整备份、v1 自动迁移 v2、导入/清空可撤销、原始数据导出；没有服务器，也就没有账号风险。
4. **本机体验更「像 App」**：PWA + Capacitor 双形态、边到边安全区、系统级本地通知、离线缓存。
5. **视觉气质更统一**：暖纸色、衬线金额、深松绿主卡；这次动效没有引入另一套视觉语言，而是围绕现有质感做「轻、稳、有方向」。

### P1：下一阶段最值得补的功能

1. **工作日 / 休息日 / 法定节假日自动倍率**
   - 价值：这是「记工时」「安心记加班」「Supershift」共同覆盖的核心需求，能显著减少每次手改倍率。
   - 代价：需要节假日数据（内置或可导入）、规则优先级（班次默认 < 日期规则 < 单条覆盖），以及历史快照策略。
   - 建议：先做「周末规则 + 手动标记节假日」，再做自动节假日库；所有倍率继续写入记录快照。
2. **批量补记 / 批量编辑**
   - 价值：漏记一整周时，比一天一天点快一个数量级；安心记加班把它作为卖点。
   - 代价：多日期选择、冲突检测（已存在记录/排班）、批量删除的撤销。
   - 建议：复用轮班表生成的多日期交互，先做「复制上一班到多天」，再做批量编辑。
3. **CSV 导入（而不只是导出）**
   - 价值：从旧 App / Excel 迁移用户的最后一道门槛；记工时和 HoursTracker 都支持。
   - 代价：列映射、日期/时间格式、金额与倍率校验、重复行策略。
   - 建议：提供「模板下载 + 列映射 + 预览前 5 行 + 冲突跳过/覆盖」四步，不要直接吞文件。
4. **可分享的月报 / 年报图片或 PDF**
   - 价值：蓝领用户会把工资/工时截图发给家人或工友；Supershift 的 PDF 导出是付费点。
   - 代价：画布排版、字体、隐私（可隐藏金额）、系统分享。
   - 建议：先做「月报卡片」图片分享，再做 PDF；复用现有年度报告文案。
5. **Android 桌面小组件 / 通知栏持续计时**
   - 价值：Supershift、HoursTracker 的小组件和实时状态是高频入口；我们的「计时中」目前只能进 App 看。
   - 代价：原生 AppWidget / 前台服务 / 通知操作按钮 / 电池与权限适配；PWA 不能可靠替代。
   - 建议：先做 PWA manifest 快捷方式（记一班、打卡计时、月度统计），再做 Android 小组件与带「暂停/结束」的持续通知。
6. **多账本 / 多份工作**
   - 价值：兼职、临时工、家庭多人共用一个 App 的场景很常见。
   - 代价：数据模型和备份格式升级、统计口径、切换成本。
   - 建议：不要做「多用户」，做「多工作簿」；每个工作簿独立的模板、记录、排班与目标。
7. **系统日历导出 / ICS 订阅**
   - 价值：比云同步轻，能把排班带进用户已有的日历生态。
   - 代价：时区、跨夜、重复规则、更新策略。
   - 建议：先做一次性 `.ics` 导出，再做订阅 URL。
8. **可选加密云同步**
   - 价值：换机/多设备；但会破坏「无账号、数据不出本机」的叙事。
   - 建议：只做端到端加密的可选开关，默认关闭，并在文案里把「本机优先」讲清楚；短期不做团队协作。

### P2：观察，不急着做

- 个税/社保/公积金到手工资估算（政策强、维护成本高）。
- 团队排班与换班（会把我们拉进协作产品赛道）。
- Apple Watch / iOS Live Activity（当前主战场是 Android + PWA）。
- 农历、节假日、天气等日历装饰信息（排班助手有，但不是我们的核心差异）。
- 记账分类/支出账本（会稀释「工时账本」的定位）。

## 4. 动效设计依据

动效不是「加一点动画」，而是让状态变化更容易被理解。以下原则来自公开的设计规范与可用性研究，并直接对应到实现：

| 原则 | 依据 | 我们的做法 |
| --- | --- | --- |
| 时长 100–500ms，高频操作更短、更克制 | NN/g：多数动画应在 100–500ms；越常见越短、越不明显 | 页面切换约 340ms，浮层进场 380ms / 退场 220ms，按压反馈 160ms，Toast 200ms |
| 移动端全屏过渡约 300ms，进场约 225ms、退场约 195ms，超过 400ms 会觉得慢 | Material Design duration & easing | 页面退场 120ms、进场 220ms（延迟 120ms）；浮层退场 220ms |
| 进出场使用不同曲线：进场减速、退场加速 | Material 的 deceleration / acceleration 曲线 | `--ease-enter: cubic-bezier(.22,1,.36,1)`，`--ease-exit: cubic-bezier(.4,0,1,1)` |
| 先退后进，避免两个页面同时可读造成重影 | Material fade-through 思路 | 旧页先淡出，等旧页退场后再淡入新页；不用全屏交叉淡化 |
| 拖动要跟手，松手要有物理结果 | iOS/Android 底部面板交互惯例 | 位移超过 96px 或速度超过 0.5px/ms 关闭，否则 340ms 回弹；背景随位移变淡 |
| 数字要可信，不能把上一个范围的数据滚成新范围的数据 | 记账/金融类产品经验 | `useAnimatedNumber` 带 `resetKey`：换月/换周期直接切值，只有同范围内变化才滚动 |
| 不要所有元素同时动 | 交错（stagger）提升层次感 | 图表柱 9ms/根、周 sparkline 28ms/根、记录分组 24ms/组，且有上限，避免长尾 |
| 尊重系统「减少动态效果」 | MDN `prefers-reduced-motion`；NN/g 也强调眩晕风险 | CSS 全局降级；JS 里的 View Transition、金额滚动、振动都直接跳过 |
| 动画只做 transform/opacity，避免触发重排 | Web 性能常识 | 浮层、月历、Toast、导航 pill 都用 translate/scale/opacity；进度条用 scaleX |
| 渐进增强，老设备不能坏 | View Transition API 支持情况 | 支持时用浏览器原生快照过渡；不支持时回退到 CSS `screen-in`；再不行就是瞬时切换 |

参考链接见文末。

## 5. Motion 2.1 动效清单（已实现）

### 5.1 页面与导航

- **Tab 切换**：旧页 120ms 淡出 + 10px 横移；新页延迟 120ms、220ms 淡入 + 14px 横移。方向由 Tab 顺序决定：记录 → 日历 → 统计 → 设置为前进，反向为后退。
- **原生 View Transition**：用 `document.startViewTransition` + `flushSync` 把截图过渡交给浏览器；`.app-main` 临时获得 `view-transition-name: app-screen`，避免整个页面（含底栏）一起淡入淡出。
- **底栏指示器**：从「每个 Tab 各自换底色」改成单枚滑动 pill，按实际布局测量，窗口尺寸变化会重新测量；Tab 切换时只让 pill 移动，图标做 360ms 的轻微弹动。
- **首屏**：`.app-shell` 只做 240ms 透明度淡入，不使用 transform，避免给 fixed 浮层制造错误的包含块。

### 5.2 浮层与弹窗

- **底部浮层**：
  - 顶部增加抓取条（grabber），标题栏和抓取条都可下拉。
  - 入场 380ms 的 easeOutCubic 曲线：前 60ms 只走约 27%，避免旧版 300ms 前 60ms 就冲过 67% 的突兀感；面板底部始终贴住屏幕，不做会露出底缝的过冲。
  - 拖动时位移有阻尼（超过 160px 后阻力增大），背景黑度随位移线性变淡。
  - 松手判定：位移 > 96px 或速度 > 0.5px/ms 则关闭，否则弹簧回位。
  - 关闭统一走 App 层 `sheetClosing` 状态：先播 220ms 退场，再从 DOM 卸载；保存、删除、返回键、Esc、关闭按钮、点背景都走同一条路径。
  - 打开浮层时锁住 `.app-main` 滚动，同时用 `scrollbar-gutter: stable` 预留滚动条槽位，避免桌面端锁滚动时内容宽度跳变。
- **确认弹窗**：入场保持 240ms 的缩放淡入；取消/确认都先播 160ms 退场，再执行动作，避免「点完瞬间消失」。
- **Toast**：
  - 入场 260ms 弹性上浮；退场 200ms 下移缩小。
  - 底部有一条 2px 的剩余时间条，普通提示 2.6s、带「撤销」6s。
  - 成功图标用 stroke-dash 描边画出勾，而不是直接出现。
  - 退场动画结束后才真正卸载，撤销按钮的点击不会被卸载打断。
  - 保存 / 删除触发的 Toast 会等浮层退场 220ms 后再出现，避免和正在下滑的面板叠在一起。

### 5.3 数据与图表

- **金额滚动**：首页本月收入、本周收入、统计合计、月目标百分比、年复盘全年收入、日历当月收入/预计，在数值变化时从当前值缓动到新值。
- **范围切换**：`resetKey`（月份/周起始/年份/统计周期）变化时直接切到新值，避免「11 月 0 元」从 10 月金额滚下来的荒谬中间态。
- **进度条**：目标进度、排班对账完成率、班次构成占比、收入预测进度，首次出现时从左侧 scaleX(0) 展开；后续宽度变化走 450ms 过渡。
- **图表**：日/周/年柱状图按索引交错生长；周 sparkline 单独交错；图表轴淡入；点击柱子时焦点文案做 200ms 轻微切换。
- **列表**：首页按天分组的记录以 24ms/组交错上浮，最多延迟 8 组，长列表不会等太久。

### 5.4 日历

- **月份切换**：左右箭头或「回到本月」触发方向感知的网格滑入（16px + 淡入，300ms）。
- **左右滑动**：跟手位移（上限 22px）+ 卡片临时阴影；松手 56px 阈值切月，否则 320ms 回弹；切月后抑制误触点击 380ms。
- **选中日**：只做背景、描边和阴影的颜色过渡，不做缩放；避免点击日期打开浮层时，背景日历的选中格被拉伸。今天/选中的颜色过渡更柔和。
- **日详情**：日期或「记录/排班」模式变化时，详情区 240ms 淡入上移；避免切换模式时内容硬切。
- **月份金额**：同月数据变化滚动，换月立即切换到新月份的值。

### 5.5 主题与触感

- **主题切换**：从点击的「深色/浅色/跟随系统」按钮中心做 460ms 圆形显影；不支持 View Transition 或用户开启减少动态效果时直接切换。
- **Android 触感**：切换 Tab 10ms；保存/开始/结束打卡两段式 12/28/14ms；删除 18ms。只在 `navigator.vibrate` 可用且用户未开启减少动态效果时触发；`AndroidManifest.xml` 增加 `VIBRATE` 权限。
- **按压反馈**：主要按钮 0.96 缩放；日历日改为背景加深而不是缩放，避免背景日历出现拉伸；快捷班次卡/结算卡 0.985；列表行改为背景加深而不是缩放，避免破坏列表边缘。
- **开关**：滑块使用带轻微回弹的曲线，按下时滑块会短暂变宽，模拟物理挤压。

### 5.6 降级与可访问性

- `initMotion()` 在启动时写入 `data-motion="view-transition" | "css"`；CSS 只在不支持 View Transition 时启用旧的 `screen-in`，避免双动画。
- `prefersReducedMotion()` 在 JS 侧统一读取 `prefers-reduced-motion: reduce`，跳过 View Transition、金额滚动和振动。
- CSS 全局 `@media (prefers-reduced-motion: reduce)` 把动画/过渡压到 0.01ms；另外显式关闭 hero 脉冲、计时圆点脉冲和 View Transition 伪元素动画。
- 浮层焦点陷阱、Esc 关闭、返回键关闭、`aria-modal`、`aria-label` 全部保留；动画不阻塞这些交互。
