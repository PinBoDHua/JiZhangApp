# 工时账本 2.5.1 发布计划与验收

- 版本：2.5.1
- 日期：2026-11-02
- 基线：2.5.0（205 个测试、Capacitor 8、Android API 36）
- 主题：**把「算对」和「不丢数据」补牢**

## 1. 为什么是 2.5.1

2.5.0 是一次纯 UI/UX 打磨，功能面没有变化。随后做了一次全量审计（`docs/audit-2.5.0.md`），在数据层、计薪链路和交互边界上发现 31 项问题，其中 6 项会直接影响金额或数据完整性：

- 打卡计时与轮班表把计薪倍数硬编码为 1，开启日期倍率后同一天两种入口金额不一致；
- `reload()` 会把校验过滤后的集合写回磁盘，坏条目被永久删除；
- 跨标签页同步先 flush 本页旧快照，反而覆盖另一页刚写入的数据；
- 重复排班预览的班数 / 金额与实际保存不一致；
- 打开「结束打卡」会冻结计时，取消后暂停时长被当成休息扣款。

2.5.1 不加新功能，只修这些缺陷，并补上对应的回归用例与 CI。存储键、备份格式、计薪口径全部不变，2.5.0 的数据可直接沿用。

## 2. 范围

| 方向 | 内容 | 验收 |
| --- | --- | --- |
| 计薪 | 打卡 / 轮班表接入 `dayRule`；结束打卡不再自动暂停 | 周六打卡与周六手动记账金额一致；关掉面板后计时继续走 |
| 数据安全 | `reload()` 不回写过滤结果；跨标签页不覆盖；写盘失败常驻提示 | 坏条目仍能从「导出副本」找回；双标签页编辑互不覆盖 |
| 排班 | 预览与保存同口径；批量补记按班次判定；对账跨月判定 | 预览班数 == 实际创建班数 |
| 交互 | 统计周期受控；浮层脏检查；标准工时光标精度 | 误触遮罩不再丢表单 |
| 平台 | 备份规则限定 `app_webview/`；快捷方式只认 `gongshi://`；导出清理缓存 | APK 构建通过、安装后功能正常 |
| 工程 | 新增 CI（typecheck / lint / test / build） | GitHub Actions 首次运行通过 |

### 明确不做

- **跨标签页逐条合并**：需要墓碑标记才能正确处理「删除」，属于设计变更，留待后续版本。
- **结算快照冻结**：已结算月份的「应发」仍按当前记录实时重算，是否冻结需产品确认。
- **大集合写盘分片**：当前已按集合合并 + 200ms 节流，没有实测卡顿数据前不做。
