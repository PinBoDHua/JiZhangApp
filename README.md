# 工时账本

一款手机优先的班次工时与收入记录 PWA。记录白班、夜班或自定义班次，按时薪与加班规则自动计算每一班的收入，并按月、按年汇总。

2.3 不加新功能，是一次结构、性能与边界的整理：数据层与页面动作层拆分、派生数据改为单次遍历、跨标签页同步与导入边界补齐，存储键和备份格式保持不变。2.0 起，工时账本从「记录工具」升级为「收入工作台」：支持分段加班计薪、本月收入预测与年度复盘，数据格式也升级到 v2（自动迁移，兼容导入 1.x 备份）。2.1 则把高频操作的手感补齐：页面、浮层、月历、数字和图表都有克制的过渡，并完整尊重系统的「减少动态效果」设置。2.2 把「算对」和「补记」做顺手：周末与节假日自动带出倍数、一次补齐一段时间的漏记、CSV 表格导入，以及桌面长按快捷方式。

## 功能

- 班次模板：每种班次可单独设置默认时间、休息时长、时薪和标记颜色
- 日期倍率：周末与节假日可自动带出计薪倍数（周末默认 2×、节假日默认 3×，可分别修改）；节假日日期可自行添加和删除，只影响新建记录、排班与批量补记，历史记录仍按当时的倍数计算
- 批量补记：选择日期区间与重复星期，一次补齐漏掉的班次；已有记录的日期自动跳过，命中的排班一并标记完成，生成后可撤销
- 表格导入：支持 CSV 导入，兼容本应用导出的表格与 Excel 手工整理的表头；按「日期 + 班次 + 开始时间」去重，导入前可看到跳过与格式错误行数
- 分段计薪：可为班次或单条记录开启「标准工时 + 加班倍数」，标准工时以内按正常倍数、超出部分按加班倍数计算；旧记录未开启时与 1.x 算法完全一致
- 计薪明细：记录、排班、打卡结算、日历和 CSV 会拆分正常工时与加班工时，工资条补充加班金额；模板可保存默认加班规则
- 自动计薪：支持跨午夜班次，按净工时 × 时薪计算，可设置 1× / 1.5× / 2× / 3× 等计薪倍数
- 收入预测：本月「已入账 + 待上排班」自动得到预计月末收入；设置月目标后，可看到按排班预计的达成率和还差几班
- 记账记录：按日期分组查看，可随时编辑或删除；历史记录保存当时的班次名称、时薪和加班规则快照
- 班次日历：记录 / 排班双模式，月历中标记实际班次或计划班次，点任意日期直接打开当天的记账或排班面板；支持左右滑动切换月份
- 排班计划：提前安排班次时间、休息、时薪和备注，可按每周同一天重复 4 / 8 / 12 周，重复时自动跳过已有排班的日期；到当天可一键打卡或转为实际记录，完成后保留在完成历史中
- 轮班表：按「白/夜/休」等预设或自定义循环，连续生成 4 / 8 / 12 周排班；已有排班的日期自动跳过，生成后可撤销
- 漏记处理：班次结束 2 小时后仍未处理的排班会出现在首页「待处理」中，可补记实际工时或标记未上
- 排班对账：月统计展示计划完成率、已完成 / 未上 / 待补记 / 待上，以及已到期计划与实际记录的工时、收入差额
- 下一班提醒：首页展示最近的排班、倒计时日期和预计收入；未来排班在当天前不会误触开始打卡
- 系统排班提醒：Android 版可按提前 30 分钟到 12 小时发送本地通知，点击通知直达对应排班；单个排班可关闭提醒或单独设置提前时间，网页版关闭后不支持定时提醒
- 打卡计时：开始、暂停休息、继续和结束结算；首页实时显示有效工时与预计收入，结束确认后生成记录；从排班开始的打卡完成后会自动完成该排班
- 快捷录入：自动沿用最近使用的班次；填表时可一键“复制上一班”，保留时间、加班规则和备注
- 本周概览：首页展示本周收入、工时、出勤、较上周变化，点击可直接进入周报表
- 周期统计：支持本周 / 本月 / 今年切换，可向前翻到未来周期预估排班收入，包含周期汇总、趋势图、单日或单月明细、班次构成和月度排班对账
- 年度复盘：年度收入、工时、出勤、平均时薪、最高收入月/单日、最长连续出勤、最常上的班次，以及 12 × 31 的年度热力图；可一键导出年度报告文本
- 工资结算：按月记录奖金、扣款和预支，查看应发与实发；支持标记到账、记录到账日期与实际差额
- 工资条：按月生成工资条，包含工时、加班、调整项、应发/实发和备注，可导出或通过系统分享
- 月度统计：月收入、总工时、出勤天数、平均时薪、每日收入柱状图、班次收入构成
- 月收入目标：设置每月目标收入，在首页和统计页显示进度与差额
- 记录搜索：按班次、备注或日期快速检索历史记录
- 长列表分段：首页默认展示最近 10 天，可分批展开更早的记录，记录再多也不会一次渲染
- 界面动效：页面切换带方向感、底部浮层可跟手下拉关闭、月历滑动切月、金额滚动、图表和进度条生长、主题圆形显影、底栏滑动指示器；系统开启「减少动态效果」时自动降级
- 触感反馈：Android 上切换标签、保存、结束打卡和删除有克制的轻触感，并跟随系统的「移除动画」设置
- 浅色 / 深色主题：可跟随系统，也可以手动锁定，适合夜班使用
- 记录管理：支持 1.25×、1.75× 等更细的加班倍数；删除记录后可立即撤销
- 本机优先：数据存储在浏览器 localStorage，不需要账号和服务器
- 备份迁移：支持 JSON 完整备份 / 恢复（含目标、外观、提醒设置、排班计划、完成历史和工资结算），以及 CSV 表格导出
- 备份兼容：2.2 备份格式为 v3，同时可直接导入 1.x 的 v1 与 2.x 的 v2 备份；1.x 数据会在首次启动时自动迁移到 v2 存储键，旧键保留只读
- 备份提醒：设置页显示上次备份时间，长期未备份时提醒导出
- PWA：支持安装到桌面/主屏幕，离线可用
- 快捷方式：Android 桌面长按图标可直接「记一班 / 打卡计时 / 批量补记 / 本月统计」；PWA 安装后同样提供这四个快捷入口

## 2.3.0 更新

**主题：把地基夯实。** 本版不加新功能，只做结构、性能、边界与测试；存储键与备份格式不变，2.2 与 2.3 的数据可互换。

- 结构：`storage.ts`（607 行）拆为 `storage/{keys,guards,backup,index}.ts`；`App.tsx`（1346 行）拆为浮层状态机、记录动作、排班动作、导入导出四个 hooks，页面只保留组合与渲染；新增 `overview.ts`（按日汇总）与 `search.ts`（记录搜索）两个纯函数模块
- 性能：首次启动不再回写 7 个集合（既省序列化，也避免把解析失败的空数组覆盖回存储）；写盘按 200ms 合并，同一集合的连续编辑只落盘一次，并在切后台/卸载前强制落盘；同一条记录的「工时 + 收入」从两次计薪降为一次；统计页月视图柱状图从「31 天 × 全量过滤」降为一次汇总 + 查表；金额滚动动画期间不再全量重算
- 修复：跨标签页数据互相覆盖（新增 `storage` 事件同步）、通知深链日期未校验导致日历跳到 NaN 年月、旧 WebView 缺 `matchMedia` 时抛错、取消分享后仍刷新「上次备份时间」
- 加固：备份导入加条目上限（记录/排班/历史各 2 万、结算 1200、单月调整项 200），CSV 导入按表单上限截断超长文本，手改坏的日期倍率规则不再让页面报错
- 无障碍：浮层与确认框打开时主内容区、底部导航加 `inert`，读屏和 Tab 不再穿透到背景
- 测试从 125 个增加到 163 个；`tsc -b`、`oxlint`、`vite build` 全部通过
- 版本号 2.3.0；Android `versionCode` 15、`versionName` 2.3.0
- 范围与验收见 [docs/release-2.3.0.md](./docs/release-2.3.0.md)

## 本地开发

```bash
npm install
npm run dev
```

打开终端输出的地址（默认 `http://127.0.0.1:5173`）。核心工时、暂停、计薪分段、收入预测、年度统计、排班日期、轮班循环、漏记检测、计划对账、提醒时间与备份恢复逻辑有单元测试：

```bash
npm test
```

类型检查（`tsc -b`，已开启 `strict`）：

```bash
npm run typecheck
```

## 构建与预览

```bash
npm run build
npm run preview
```

构建产物在 `dist/`，部署到任意静态站点即可。PWA 安装需要 HTTPS（`localhost` 除外），部署到 Vercel、Netlify、Cloudflare Pages 等平台后，在手机浏览器菜单中选择「添加到主屏幕」。应用按站点根路径 `/` 部署；如需部署到子路径，请先调整 `vite.config.ts` 的 `base` 和 manifest 中的路径。

## Android APK

最新安装包在 `release/` 目录：

- `release/工时账本-2.3.0.apk`
- `release/GongshiLedger-v2.3.0.apk`（同一安装包，英文文件名）

把 APK 传到手机后点击安装，首次安装需要在系统中允许「安装未知应用」。应用完全离线运行，数据保存在手机本地。

重新构建 APK（Capacitor 8 需要 JDK 21 与 Android SDK 36；本机 SDK 位于 `D:\Android\Sdk`，免安装 JDK 21 位于 `D:\tools\jdk-21`）：

```powershell
$env:JAVA_HOME = 'D:\tools\jdk-21'
npm run build
npx cap sync android
cd android
.\gradlew.bat assembleRelease
```

构建产物：`android/app/build/outputs/apk/release/app-release.apk`

目标版本是 Android 16（API 36）。从 Android 15 起系统强制边到边，状态栏与导航栏会覆盖在页面之上，因此 `capacitor.config.ts` 启用了 `SystemBars.insetsHandling: 'css'`，CSS 通过 `--safe-top` / `--safe-bottom` 变量（优先读 Capacitor 注入的 `--safe-area-inset-*`，其次读 `env(safe-area-inset-*)`）留出空间；状态栏图标的明暗由 `SystemBars.setStyle` 控制。

发布签名配置在 `android/keystore.properties` 和 `android/keystore/shift-ledger.jks`。这两个文件不进入版本控制，但必须妥善保留；后续更新 APK 需要使用同一签名才能覆盖安装。升级时同时在 `android/app/build.gradle` 提高 `versionCode`。

Android 桌面图标和启动页由以下命令重新生成：

```bash
npm run android:assets
```

## 数据说明

- 数据保存在 localStorage 的 v2 键（键结构自 2.0 起未变）：记录 `shift-ledger.records.v2`、班次 `shift-ledger.templates.v2`、偏好 `shift-ledger.preferences.v2`、排班 `shift-ledger.plans.v2`、完成历史 `shift-ledger.plan-history.v2`、工资结算 `shift-ledger.settlements.v2`、进行中的打卡 `shift-ledger.active-shift.v2`
- 首次启动会把 1.x 的 `*.v1` 键原样复制到 `*.v2`，并写入 `shift-ledger.meta.v2`（`schemaVersion: 2`）；旧键保留只读，升级后不会丢失原数据
- 记录里可能带 `overtime: { standardMinutes, multiplier }` 作为当时的加班规则快照；没有该字段的旧记录继续按整班单倍数计算
- 系统提醒由 Android 本地通知实现，通知权限和精确闹钟权限由系统管理，不会随 JSON 备份迁移；换机或重装后需要在设置中重新开启
- Android 触感反馈使用系统振动权限（`VIBRATE`），不需要运行时授权；关闭系统的触感/动画后应用会一起静音降级
- 排班计划保存在 v2 键，会随 JSON 备份一起导出和恢复；导入旧版不含排班的备份时会保留现有排班
- 已完成或标记未上的排班保存在 v2 完成历史键；新版备份会包含完成历史，导入旧版不含完成历史的备份时会清空现有完成历史
- 工资结算保存在 v2 键，同样会随 JSON 备份导出和恢复
- 正在进行的打卡计时单独保存在 v2 键，包含暂停、休息时长和来源排班；确认结束后转为正式记录
- 日期倍率规则（`dayRule`）保存在偏好里，包含周末倍数、节假日倍数与节假日日期列表；它只决定新建记录时带出的倍数，记录本身仍保存当时的倍数快照
- 备份格式为 `version: 3`，额外包含应用版本、提醒设置与日期倍率规则；仍可导入 1.x 的 `version: 1` 与 2.x 的 `version: 2` 备份，旧备份不会覆盖当前日期规则
- 清理浏览器数据会一并清除账本，建议在「设置 → 导出备份」定期备份
- 导入备份会覆盖当前记录、班次、结算、完成历史和排班（旧版无排班的备份除外）；新版备份还会恢复月收入目标、外观和提醒设置
